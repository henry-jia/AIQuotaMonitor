**中文文档 | [English](README.en.md)**

Windows 11 桌面小工具：把多个 AI 套餐的配额（5 小时用量、7 天用量、30 天用量……）集中显示在一个无边框半透明的小部件里。

大多数 AI 供应商**没有配额 API**，所以本工具的做法是：给每个服务配一个网址，用内置 WebView2 定期打开该页面（通常是已登录状态），按你在设置界面里配置的提取规则从页面上抓取配额数值。规则默认是「**按标签自动定位**」——只要标签和页面上显示的文字一致（如「每周使用额度」）就行，不需要任何 CSS 知识；高级用户也可以填 CSS 选择器精确控制。全程图形化配置，不需要手改任何文本文件。

## 功能一览

- 无边框圆角深色半透明小部件，按住空白处拖动，位置自动保存；置顶可开关；不透明度可调；**背景色可设定**（取色对话框含屏幕取色器；Win11 毛玻璃下该色作为 tint，alpha 决定透出程度）；**滚轮整体缩放界面（含文字），标题栏 100% 按钮一键还原**
- **Windows 11 原生化**：小部件用 DWM **Acrylic 毛玻璃**、设置/历史/取色窗口用 **Mica**，深色沉浸、圆角与系统 8px 对齐；图标按钮换 **Segoe Fluent Icons**（刷新/暂停/关闭/警告），hover/pressed 分层反馈；Win10 自动降级为实色圆角
- 每个服务一张卡片：主题色圆点 + 名称（**Ctrl+点击直接在浏览器打开官方用量页面**，按住 Ctrl 时名称变链接样式）+ 最后刷新时间（订阅行右侧小字，今天显示时分、跨天带日期）；每条配额一行：标签 + 百分比 + 细进度条 + 用量明细/重置时间
- **全局颜色主题**：进度条按 4 种语义状态着色——**正常**（主题主色）、**接近基准**（用量距时间基准线 10 个百分点以内；无基准时 ≥60%）、**超出基准**（用量跑在时间前面）、**90% 告警**（用量 ≥90% 优先于其他状态）。内置蔚蓝/翡翠/紫罗兰/落日/石墨 5 套预设一键切换，也可选「自定义」逐色修改（颜色选择对话框带屏幕取色器），见下文「颜色主题」
- **时间基准线**：进度条上的竖线 = 按时间均匀消耗此刻应到的位置（5 小时窗口过半在 50%，7 天窗口第 4 天在 57%）。**白芯深边** = 用量未超线（余量健康）；**红芯白边** = 用量已超线（用得偏快，注意省着用）；悬停进度条有文字说明。窗口长度从规则标签推断（`5 小时`/`5-hour`→5h、`7 天`/`周`/`week`→7 天、`月`/`month`→30 天），标签不含窗口信息或没有重置时间则不显示；可在设置里全局开关
- 纵向罗列 / 横向铺开两种布局，窗口自动适应内容大小
- 定时自动刷新（默认 5 分钟，全局/单服务均可配），后台顺序执行不卡 UI
- 标题栏 ⟳ 强制刷新全部服务；**每张卡片右上角也有 ⟳，只刷新该服务**；刷新期间显示「刷新中…」且按钮禁用，点击一定排队执行不丢失
- **暂停抓取**：标题栏 ⏸ 全局暂停（也可在右键/托盘菜单勾选「暂停抓取」），每张卡片的 ⏸ 单独暂停该服务——暂停期间**完全不访问供应商**（规避风控/敏感时期），但倒计时与基准竖线仍每分钟本地更新，已有数据保留显示（卡片置灰标记「已暂停」）；恢复后立即补抓。设置里也可按服务勾选
- 右键菜单 + 系统托盘菜单：立即刷新 / 置顶 / 布局切换 / 设置 / 显示隐藏 / 退出，托盘双击显示/隐藏
- 异常状态：「需要登录」卡片带**去登录**按钮（弹出内置浏览器手动登录，关闭后自动重新抓取）；抓取失败显示红字错误，tooltip 有完整信息
- **陈旧数据回退**：刷新失败（timeout、导航失败等）但此前成功抓过时，卡片**保留显示上次数据**并加琥珀色小字「⚠ 刷新失败，当前显示 HH:mm 的数据」（hover 看完整错误）；重启后立即显示上次会话数据并同样标记，首次成功刷新自动替换。「需要登录」仍显示专属卡片，不掩盖重新登录的行动
- **用量历史**：每次成功刷新按配额行记录一条百分比样本（仅存本机 `history.jsonl`，保留 30 天、超 7 天自动稀释）。**点击配额行**打开历史窗口：24 小时 / 7 天 / 30 天趋势图（重置锯齿分段绘制）+ 当前 / 区间增量 / 速率 / **按近 24 小时速率预测重置时到几 %**。全局设置可关闭记录
- WebView2 使用共享用户数据目录（`%LOCALAPPDATA%\AIQuotaMonitor\WebView2UserData`），**同一域名只需登录一次**

## 快速开始

1. 下载或自行构建 `AIQuotaMonitor.exe`（自包含单文件，不依赖 .NET 运行时，唯一要求是系统装有 WebView2 Runtime——Windows 11 一般自带）。
2. 直接双击运行。首次启动会在 **exe 同目录**生成 `config.json`（内含一个未启用的示例服务）。
3. 在小部件上**右键 → 设置…**，把示例服务改成你的服务，或点「添加」新建。

> 建议把 exe 放在一个固定目录（如 `D:\Tools\AIQuotaMonitor\`）再运行，配置文件会保存在 exe 旁边。

## 如何添加一个服务（完整示例）

假设你在用某个 AI 服务，它的控制台有个用量页 `https://console.example.com/usage`，页面上显示「本周期已用 42%」和「12 / 50 次 · 3 天后重置」。

1. **先登录**：设置里添加服务并保存后，卡片会显示「需要登录」，点「去登录」在内置浏览器里登录一次即可（之后共享登录态）。
2. **配服务**：
   - 名称：`示例 AI`
   - 网址：`https://console.example.com/usage`
   - 额外等待秒数：`10`（这是**超时上限**而非死等——工具会每 0.5 秒轮询页面，任一定位文本出现就立即开始抓取，快的话 1 秒就完成；渲染慢的 SPA 会等到上限）
   - 未登录指示选择器：可选。如果未登录时页面上总有「登录」按钮，就填它的选择器（如 `.login-btn`），命中即判定未登录
3. **配规则**（点「添加」，CSS 选择器全部留空即可）：
   - 规则一：标签 `5 小时用量`，类型 `百分比`，正则点预设「百分比 %」→ `(\d+(?:\.\d+)?)\s*%`
   - 规则二：标签 `30 天用量`，类型 `用量对`，正则点预设「a/b 用量对」→ `(\d+)\s*/\s*(\d+)`。重置时间不用配，会自动识别页面上的「重置时间：…」
4. **调试**：选中该服务，点「**测试抓取**」。下方会显示每条规则抓到的原始文本和解析结果——标签没命中就把标签改成页面上的一字不差的文字；数值不对就根据原始文本调整正则，直到解析正确。
5. 保存后立即生效：重建卡片、重启定时器；**只有新增或配置有变化的服务会重新抓取**，没动过的服务保留现有数据和刷新节奏（想强制全部刷新，点小部件上的 ⟳）。

**工作原理（自动定位模式）**：工具在页面上找到显示「标签」文字的元素（如「每周使用额度」标题），然后从它向上找到包含数值的容器区域（通常就是那张用量卡片），在区域内用正则取第一个匹配的数字，并在同一区域内自动识别重置时间（「重置时间：…」「…后重置」「将于…重置」「Resets in …」都能认）。搜索范围包括主文档和所有同源 iframe；如果还是全部抓不到，说明内容可能在**跨域 iframe** 里（同源策略导致 JS 读不到，阿里云控制台就是这样——登录窗口里能看到内容是因为渲染不受限），此时工具会自动收集这些 iframe 的地址、直接导航过去再抓一遍。标签就是定位锚点，所以**标签必须与页面显示文字一致**。

**多语言页面**：有的网站会按浏览器语言显示不同文字（比如你的浏览器里是「5 小时用量」，工具内置浏览器里可能是「5-hour usage」）。工具的内置浏览器已设置为中文环境，多数网站会直接渲染中文；如果个别网站仍显示英文，在规则的「**定位文本**」里填多个别名、用 `|` 分隔即可，如 `5 小时用量|5-hour usage`，命中任意一个都算（此时标签保持中文，只影响卡片显示名）。

**何时需要 CSS 选择器**（高级）：当同一个标签文字在页面上出现在多个区域、或标签与数值不在同一容器时，可以填写 CSS 选择器把范围精确锁定到目标元素（浏览器 F12 右键元素 → 复制 selector）。填了选择器就走「选择器模式」：正则只在该元素文本内匹配。

## 规则字段说明

| 字段 | 说明 |
| --- | --- |
| 标签 | 卡片上显示的名称，如「5 小时用量」。**自动定位模式下它还是默认的定位锚点**，需与页面显示文字一致 |
| 定位文本 | 可选。留空 = 用标签定位；多语言页面可填多个别名，用 `|` 分隔（如 `5 小时用量|5-hour usage`），命中任意一个即可 |
| 类型 | `百分比`：页面直接给出 xx%；`用量对`：页面给出 a / b，自动算百分比并显示明细「a / b」 |
| CSS 选择器 | **留空（推荐）**= 自动定位：按标签文字在页面上找数值区域；填写 = 选择器模式，正则只在该元素文本内匹配 |
| 正则 | 第一个捕获组是数值；百分比预设 `(\d+(?:\.\d+)?)\s*%`，用量对预设 `(\d+)\s*/\s*(\d+)`（两个捕获组） |
| 数值为剩余百分比 | 可选。页面显示「剩余」而非「已用」时开启（如 `73% remaining` → 显示已用 27%），仅百分比类型生效 |
| 重置选择器 | 可选。仅选择器模式生效。抓取重置时间文本用的选择器，留空对整页匹配 |
| 重置正则 | 可选。自动定位模式下留空会自动识别「重置时间：…」「…后重置」「Resets in …」；自定义时第一个捕获组作为展示文本，不区分大小写 |

服务级字段：名称、网址、额外等待秒数、未登录指示选择器（可选）、刷新间隔（可选，留空用全局）。

## 颜色主题（全局设置）

所有卡片共用一套**全局配色**，按语义分 4 种状态色 + 1 个强调色：

| 色板 | 语义 |
| --- | --- |
| 强调色 | 卡片服务圆点 |
| 正常 | 用量落后时间基准线较多（无基准线时 <60%） |
| 接近基准 | 用量距时间基准线 10 个百分点以内（无基准线时 ≥60%） |
| 超出基准 | 用量跑在时间基准线前面（用得偏快） |
| 90% 告警 | 用量 ≥90%，优先级最高 |

「全局设置」顶部的**颜色主题**下拉提供 5 套预设：**蔚蓝 / 翡翠 / 紫罗兰 / 落日 / 石墨**，选中即预览（下方五行色板同步显示该主题色），保存后生效。

选「**自定义**」后五行色板变为可点击：点击色块打开**颜色选择对话框**（大色块预览、`#RRGGBB` 输入、R/G/B 滑块）。对话框里的「**屏幕取色**」按钮可拾取屏幕上任意颜色：点击后整屏冻结，移动光标时旁边显示 7×7 像素放大镜和当前 hex，**左键单击取色，Esc 或右键取消**。

配置存于 `config.json` 的 `theme` 字段（`name` 为预设 key 或 `"custom"`，自定义时另存五个 hex）；旧配置没有 `theme` 字段时自动使用「蔚蓝」，老版本的服务级 `color` 字段仍保留但不再生效。

## 重置时间的解析与显示（全局设置）

工具抓到重置文本后会立刻解析成**绝对时间**存起来（所以「2 小时后重置」这类相对时间不会越显越不准），支持的原文格式包括：`重置时间：16:33`、`重置时间：2026-07-26 10:00`、`07-23 14:44 后重置`、`2026-08-17 后重置`、`2026-07-23 15:42:00 重置`、`将于 2026年7月29日 1:04 重置`、`Resets in 07-23 14:44`、`Resets Jul 29, 2026 1:04 AM`（英文月名）、`3 天后重置`、`3天9小时29分钟后重置` 等；解析失败则原样显示原文。

全局设置里有这些开关：

- **统一重置时间格式**（默认开）：各家供应商日期格式五花八门，开启后按统一格式显示。格式框提供预设（`MM-dd HH:mm`、`yyyy-MM-dd HH:mm`、`MM月dd日 HH:mm`、`HH:mm`），也可以手动输入任意 .NET 日期格式串。
- **重置倒计时分级预警**（随每分钟界面重绘自动变色）：短窗口（≤24h，如 5 小时）剩 **1 小时**变黄、**30 分钟**变橙红；长窗口（7 天/30 天）剩 **24 小时**变黄、**2 小时**变橙红——窗口快重置、剩余额度抓紧用。**套餐到期**同理：剩 **5 天**变黄、**1 天**变橙红。颜色取自主题语义色（黄=接近、橙红=超出），随主题切换

## 未登录处理流程

1. 配置了「未登录指示选择器」：抓取时页面上命中该选择器 → 卡片显示「需要登录」+ 去登录按钮。
2. 未配置：所有规则都抓不到值 → 判定「抓取失败（可能未登录或页面结构变化）」，同样给出「去登录」按钮。
3. 点「去登录」弹出内置浏览器（与抓取共享登录态），手动登录后**直接关闭窗口**，工具自动重新抓取该服务。

## 配置存储

`config.json` 保存在 **exe 同目录**（`System.Text.Json`，camelCase）：服务列表与规则、窗口位置、置顶、不透明度、布局方向、刷新间隔都在其中，每个服务带一个稳定 `id` 字段（用量历史按它关联）。正常情况不需要手改——拖动窗口、切换置顶/布局都会自动保存。

## 订阅到期与自动续费（智能扫描，零配置）

工具会在抓取配额时顺带扫描页面全文（含同源 iframe），自动识别订阅信息并显示在卡片名称下方，如「订阅 31 天后到期 · 自动续费 关」：

- **到期时间**支持的写法：`结束时间 2026-08-24`、`剩余天数 31 天`、`下次自动续费时间：2026-08-17`、`08月03日自动续费`、`will be canceled on Aug 19, 2026` 等；剩 **5 天**变黄、**1 天**变橙红提醒
- **自动续费**：识别「自动续费 开启/未开启」文本、「下次自动续费时间」等隐含信息，以及页面开关控件（switch/checkbox）的实际状态
- 如果订阅信息**不在用量页**（如智谱在「套餐概览」页、Codex 在 Billing 页），在服务的「订阅信息网址」里填那个页面即可；这类服务按 6 小时缓存抓取订阅信息，不会每次刷新都多开一页。留空则在用量页面上顺带扫，零成本

## 用量历史与陈旧数据回退

两个文件都保存在 `%LOCALAPPDATA%\AIQuotaMonitor\`，仅存本机、不上传：

| 文件 | 内容 |
| --- | --- |
| `lastgood.json` | 每个服务最后一次成功抓取结果（刷新失败 / 重启后的陈旧数据回退源） |
| `history.jsonl` | 用量百分比时间序列样本，每行一条，如 `{"t":"2026-08-05T22:55:01+08:00","svc":"<id>","rule":"5 小时用量","pct":42,"detail":"2.1 / 5 小时","resetAt":"…"}` |

- 历史保留 **30 天**；超过 7 天的样本自动稀释为每小时一条。
- 点击卡片上的配额行打开历史窗口（24 小时 / 7 天 / 30 天切换），统计含：当前值、区间增量（自上次重置后累计）、近期速率（%/小时）、按近 24 小时速率预测「重置时约几 %」。
- 全局设置可关闭「记录用量历史」（关闭不清空已有数据，删除文件即清除）。
- 序列按规则的稳定 id 关联，**改标签后历史保留**（v1.3.0 之前的旧样本按标签回退关联）。

## 站点适配经验教训（抓取原理笔记）

这个项目在适配五家供应商的过程中踩过的坑，对配置新服务有参考价值：

1. **隐藏抓取窗口必须有正常视口尺寸**（1280x800）。曾经用 1x1 透明窗口，结果阿里云这类懒加载 SPA 靠视口/可见性触发渲染，视口过小就不生成内容 DOM，JS 永远抓空。症状是「登录窗口里一切正常，抓取就是找不到文字」。
2. **跨域 iframe：渲染可见 ≠ JS 可读**。同源策略下 JS 读不到跨域 iframe 的内容。工具的解法：收集读不到的 iframe 地址，直接把隐藏浏览器导航过去再抓（变成顶层页面即无限制）。
3. **会话级 Cookie vs 持久 Cookie**。阿里云的登录票据是会话级的，Chromium 只存内存、进程退出即失——日常浏览器感觉不到是因为它的进程常年不死。工具每次抓取后把全部 Cookie 用 DPAPI 加密落盘、启动时还原。但服务端会话到期仍无解，只能重新登录。
4. **内置浏览器语言会改变页面文案**。把 WebView2 设为中文后，Kimi/Codex 的页面文案从英文变中文，导致英文标签失效。规则的「定位文本」支持 `中|英` 多别名就是为这个准备的。
5. **轮询等待优于固定等待**。SPA 渲染时间不确定，固定等 N 秒不是慢就是空；现在是每 0.5 秒轮询，「额外等待秒数」只是超时上限。
6. **页面骨架比数据先渲染，「有匹配」不等于「数据到了」**。阿里云页面的进度条轴刻度（0% 50% 90% 100%）先于真实数值出现，曾导致抓到 0%。解法：容器内有多个匹配时取**字号最大的元素**（大数值永远比刻度字大），等待轮询也升级为「提取成功且质量达标（唯一匹配或大字号匹配）」才放行。
7. **导航失败 ≠ 页面没加载**。阿里云控制台的重定向链会让 WebView2 误报导航失败，必须检查页面实际内容再下结论。
8. **错误信息要带现场**。笼统的「抓取失败」无法排查；现在失败时会附每条规则的具体原因 + 页面标题和正文开头，一眼分清是未登录、标签不对还是页面结构变了。
9. **正则 `\b` 对中文不生效**。CJK 字符都算 word 字符，「小时用量」的「时」和「用」之间没有边界——`\b` 只能挂在英文分支上（`天|days?\b`）。这个坑在相对时间解析和窗口长度推断里各踩过一次。

## 常见问题

**Q：启动提示缺少 WebView2 Runtime？**
工具依赖 WebView2 Evergreen Runtime（Windows 11 一般自带）。缺失时程序会弹出安装提示，按提示到微软官网下载安装「WebView2 Runtime 长青版」即可：https://developer.microsoft.com/zh-cn/microsoft-edge/webview2/ 。安装后重启本程序。可通过注册表 `HKLM\SOFTWARE\WOW6432Node\Microsoft\EdgeUpdate\Clients` 下「Microsoft Edge WebView2 Runtime」项的 `pv` 值确认版本。

**Q：抓不到数据 / 显示「抓取失败」？**
打开「设置」，选中该服务，点「**测试抓取**」：
- 提示「页面导航失败」：错误信息里附了最终地址和标题——若是被重定向到登录页，先「去登录」；现在导航报错后会自动检查页面实况，有内容会继续抓（阿里云控制台这类重定向链已兼容）；
- 提示「找不到定位文本」：标签与页面显示文字不一致，改成一字不差（页面渲染慢的情况已改为轮询等待，「额外等待秒数」是超时上限，渲染慢就调大）；
- 看「原始文本」——如果是登录页内容，先点卡片上的「去登录」；
- 如果有目标数字但解析失败，照着原始文本调整正则（注意让第一个捕获组正好是数值）；页面显示的是「剩余 xx%」时记得开「数值为剩余百分比」；
- 如果标签文字在页面多个区域出现导致抓错区域，再考虑填 CSS 选择器精确锁定（浏览器 F12 右键元素 → 复制 selector）。

**Q：登录态能保持多久？**
登录信息保存在 `%LOCALAPPDATA%\AIQuotaMonitor\WebView2UserData`，同一域名只需登录一次；会话过期后卡片会再次显示「需要登录」，重新登录即可。当某个服务从正常变为需要登录时，托盘会弹气泡提醒。

**Q：为什么阿里云控制台之前每次重启工具后都要重新登录？**
根因是阿里云的登录票据（`login_aliyunid_ticket`）是**会话级 Cookie**——Chromium 只把会话级 Cookie 存在内存，浏览器进程退出即失；日常浏览器感觉不到，是因为它的进程常年不死（启动加速/后台模式）。自本版本起，工具会在每次抓取后把全部 Cookie 导出、用 DPAPI（当前用户）加密保存到 `%LOCALAPPDATA%\AIQuotaMonitor\cookies.dat`，下次启动时自动还原，会话 Cookie 也能跨重启存活。注意：这只能解决客户端会话丢失，**阿里云服务端会话本身较短**——若服务端到期，仍需点一次「去登录」（托盘会有气泡提醒）。

**Q：某个服务抓失败会影响其他服务吗？**
不会。各服务独立抓取、独立计时，单个服务失败只在它自己的卡片上显示错误。
